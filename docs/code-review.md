# 实现审查

审查基线为原始 PRD 提交 `2ca765e`，实现提交为 `107391d`；两位独立审查者分别检查规范与 PRD，随后检查修复工作区。使用 `git diff 2ca765e...107391d`，需求依据 `prd.md`，规范依据 `AGENTS.md`、`CONTEXT.md` 和审查技能的代码异味基线。

## Standards

1. **已修复：后台有效性变化没有推进控制代次。** 与 CONTEXT 的交付约束不符，旧上下文包可能继续交付。后台改变已有记忆的有效状态或项目环境时，现与变化一起发布新的控制代次。公开 Service 回归验证旧包失效。
2. **维护建议：可能的 Primitive Obsession。** 底层统一记录的 `kind` 与 `data` 仍是通用存储形状，领域服务中存在类型断言。后续可引入按类型区分的记录联合；这是维护性判断，不是已观察到的功能错误或试用阻塞项。

## Spec

1. **已修复：否定的成功表述可能晋升经验。** 旧子串匹配把“尚未验证通过”或“not verified success”当成成功。现在只有明确、完整的结果声明才可授予成功/失败状态；问句、否定完成和引用不会成为成功证据。公开 Service 测试覆盖三任务两会话不误晋升，以及真正成功晋升与反例撤回。
2. **已修复：任意 Bash 输出的项目范围无法确认。** 现在不保存任意 Bash 命令或输出正文，保留事件标识与过滤状态；只有工作区明确、执行成功、精确匹配受支持的 `--version` 命令时保留解析后的运行时名称和版本。额外正文不进入事件。
3. **已修复：Python 环境名称不一致。** 采集与记忆条件现在共享名称归一化，`python3` 与 `Python` 均使用 `python`。公共边界测试验证 Python 3.13 会使依赖 3.12 的记忆退出当前召回，并拒绝旧上下文包。

补充 AC-13 回归：尚在生成的原始事件也可被明确预览和删除；生成完成或重启均不能复活。若预览后后台改变了受影响记忆，确认删除会要求新的预览，不能扩大用户看到的删除范围。

规范轴共 2 项（1 项已修复，1 项维护建议）；需求轴共 3 项，均已修复。16 GB 性能与产品价值对比的公开发布证据仍按 [验收记录](validation.md) 单独保留，不把当前试用结果当作公开发布验收。
