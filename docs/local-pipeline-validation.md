脚本在模型准备之前替换本进程的网络请求入口，任何非 `http://127.0.0.1` 请求都立即报错，既不发出请求，也不返回伪造资源。缓存准备仍重新验证固定文件的大小和 SHA-256；两个模型及运行时均直接使用已下载文件。

最终非回环 URL 尝试数为 **0**。实际模型调用为抽取 3 次、文档向量 4 次、查询向量 8 次；返回的文档向量均核验为 1,024 维。模型启动已接入父进程生命周期监督器，联调覆盖正常退出与重新启动。

这证明应用的模型资源准备与推理调用在本次缓存条件下没有要求外网。它不是操作系统级抓包，也不表示 Claude Code 整体可以离线。

## 输入与断言

输入是脚本内的合成材料：一条中文项目依赖约束（pnpm 9、不使用 npm、legacy 子目录仍使用 yarn 1）和一条英文支付重试约束（不自动重试，重试必须携带原幂等键）。另加入一条已经记录但尚未处理的中文旧事实，复现纠正与后台任务之间的竞态。

| 步骤 | 验证结果 |
|---|---|
| 缓存准备 | 拒绝所有非回环请求时仍进入 ready |
| 记录与重试 | 两条事件可靠接收，同一事件重试 10 次仍只有一个逻辑来源 |
| 后台处理 | 真实抽取后执行真实文档向量生成，产生两条记忆，队列清空 |
| 中文召回 | 保留 pnpm 9、否定 npm 和 legacy/yarn 1 例外；向量为 1,024 维 |
| 跨语言召回 | 中文支付问题找到英文重试约束，保留否定和原幂等键要求 |
| 排队旧来源 | 纠正到达前，另一个同文旧来源仍留在处理队列 |
| 显式纠正 | pnpm 9 改为 pnpm 10 后，新查询立即排除旧正文，此时新向量尚缺失 |
| 旧任务与向量回填 | 再处理较早的排队来源不会覆盖纠正；纠正版完成真实 1,024 维向量回填 |

## 联调发现与修复

扩大测试后实际发现过一个硬门槛失败：较早记录、尚未处理的另一条同文旧事实不在纠正目标的已关联来源列表中，后台处理会按旧正文计算出原记忆 ID，并把 pnpm 10 覆盖回 pnpm 9。初次新增用例确实失败；未以“其他九步通过”忽略它。

最终实现阻止后台抽取覆盖明确用户纠正的目标，并为纠正及临时向量失败建立带版本检查的向量回填任务。重新执行真实模型流水线，旧来源竞态和向量回填断言均通过。该回归对应 PRD §10.2、AC-08 的纠正生效要求，以及 §9.2 对异步向量维护的要求。
