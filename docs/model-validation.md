## 真实执行配置

- 机器：Apple M4，32 GiB RAM，macOS 26.3 / Darwin 25.3.0，arm64，Node.js 26.7.0。当前机器不满足“只有 16 GB 内存”的基线条件，不能据此承诺 16 GB 上限。
- 生成：官方 Qwen3-8B Q4_K_M，Metal，非思考模式，固定 seed 42，temperature 0.1，单并发，context 5,120 tokens；完整模板输入最多 4,096 tokens，输出最多 768 tokens。
- 抽取：模型选择来源记录及类型，正文、证据和条件通过每批动态 JSON schema 约束为当前输入中的原文。每次取一段最多 160 个真实模型 tokens 的来源，长文本继续分片，分片保留截断标记及原来源 ID，置信度最高 0.79。模型误把没有明确第一人称偏好句式的规则标为 preference 时，适配器将其降为 fact，后续仍按来源角色决定权威级别。模型不生成或执行维护代码。
- 向量：Qwen3-Embedding-0.6B Q8_0，`--embedding --pooling last`，维度 1,024，输出再次做 L2 归一化；查询采用清单内固定英语 instruction，文档不加查询 instruction。实际输出维度与范数检查通过。
- 每个模型服务只监听 `127.0.0.1`，使用独立随机 256-bit 访问凭据，凭据通过子进程环境传入，不出现在启动参数；关闭 Web UI，推理日志不保留对话正文。没有云推理入口。

上述 last pooling 与指令形式参考 [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF/tree/370f27d7550e0def9b39c1f16d3fbaa13aa67728)，本次通过真实检索句对核验。进程参数、模板计数和 JSON schema 接口按 [固定 llama.cpp 服务文档](https://github.com/ggml-org/llama.cpp/blob/5266f24da75dc449bd56cbed7addb9c8e4a6a73e/tools/server/README.md) 实现。

## 小样本结果与失败修正

可复跑：`npm run evaluate:models`。该脚本只使用脚本中明确列出的合成样本，报告包含原始模型输出、适配器最终输出和每个查询的排名；不会导入或记录用户历史。实际结果保存在 [`model-evaluation.json`](model-evaluation.json)，本次时间为 `2026-09-11T12:52:11.132Z`。

固定集包含 12 条来源、50 个预标注检查字段（原文中的数字、否定、例外、版本及类型），语义检索语料 16 条，12 个不同中英文查询各执行两遍，共 24 次。

| 检查 | 实际计数 |
|---|---:|
| 抽取适配器字段正确 | 50 / 50，100% |
| 关键证据引用有效 | 12 / 12，100% |
| Recall@6 | 24 / 24，100% |
| Top1 命中 | 24 / 24，100% |

初始自由字符串抽取未达标：50 个字段仅通过 25 个，原因包括中文句号和引号被改写、模型生成了来源中没有的条件标签，以及省略同一事件的例外。没有把这些结果按“JSON 合法”记为通过。最终使用动态 schema 将来源字段限定为当前事件原文，并保留完整短来源上下文。本次 8B Q8_0 对照运行还把两条项目规则误标为 preference；公共适配器按明确第一人称句式修正该类型后，8B Q4_K_M 固定集通过。**上述 100% 衡量的是保守抽取适配器，不能解释为模型自由归纳或复杂推理准确率 100%。** 未知字段、无效来源、推断用户偏好和超长输出依然会被拒绝或留作低置信候选。

## 时间、资源与生命周期

| 项目 | 本次测量 |
|---|---:|
| 已缓存文件的重新 SHA 校验＋embedding 进程冷启动 | 3,420 ms |
| 首条生成（含生成进程冷启动） | 13,820 ms |
| 后续 11 条抽取 | 5,161–11,969 ms / 条，平均 8,348 ms |
| 热查询 embedding API p95，24 次 | 24.28 ms |
| 两模型子进程合计采样峰值 RSS | 7,044,576 KiB，约 6.72 GiB |

本次评测紧接模型下载，运行时模型文件仍可能位于系统页缓存中；首次生成包含进程和 Metal 初始化，但不能视为重启机器后的物理冷盘结果。缓存状态不同的结果不可合并成同一热态延迟指标。RSS 由每 250 ms 采样的系统进程报告取得，递归统计监督器之下的 llama-server 子孙进程，并非完整统一内存或 GPU 峰值计量。

资源未就绪时立即返回 `MODEL_PREPARING`；不在调用者请求里同步开始多 GB 下载。前台向量查询默认 350 ms 超时，抢占后台生成，调用者使用文本检索降级。生成空闲 60 秒后卸载；shutdown 中止请求及下载并关闭模型子进程。已确认的事件与可恢复任务由统一数据库负责，模型模块不保存第二份业务状态。

9 项模型公开边界测试及 3 项进程监督测试通过。监督测试包含 kernel 被 SIGKILL 后 5 秒内回收顽固模型进程；新增恢复回归先确认生成进程崩溃后 retry 仍卡在 degraded 的失败，再验证修复后恢复 ready 并可再次抽取。模型测试覆盖：固定 8B 清单、续传后原子发布、已有正确缓存离线复用、服务端忽略 Range、校验失败后禁止自动重试、磁盘不足前置失败、网络失败状态跨重启保留、并发下载去重、来源和类型校验、维度及归一化、空闲卸载、显式停机和前台超时（部分项目在同一测试内）。
